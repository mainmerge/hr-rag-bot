# HR RAG-бот DemoTech

Учебный RAG-бот (Retrieval-Augmented Generation), который отвечает на вопросы сотрудников по HR-политикам
вымышленной компании **DemoTech**: отпуска, больничные, удалёнка, онбординг, командировки, обучение,
увольнение, ДМС. Бот отвечает **только** по найденным фрагментам документов, указывает источник,
а если ответа нет — честно говорит «В документах нет информации».

Главная часть проекта — **воспроизводимая оценка качества**: retrieval hit@3, точность ответов
через LLM-as-judge и доля правильных отказов на вопросах «с подвохом».

> Все документы в `docs/` — демонстрационные, компания и цифры вымышлены.

## Стек

| Компонент | Технология |
|---|---|
| Эмбеддинги | `intfloat/multilingual-e5-small` (sentence-transformers, локально, CPU) |
| Векторная БД | ChromaDB, локально в `chroma_db/`, косинусная метрика |
| LLM | Google Gemini через SDK `google-genai` (по умолчанию `gemini-flash-latest`) |
| UI | Streamlit |
| Оценка | собственный `eval.py`: hit@k, MRR, LLM-as-judge |

## Архитектура

```
             ┌──────────── ingest.py (офлайн) ─────────────┐
docs/*.md ──►│ чанкинг ~500 симв. ─► e5 "passage:" ─► Chroma│──► chroma_db/
             └─────────────────────────────────────────────┘

             ┌──────────────── rag.answer() ──────────────────────────────┐
вопрос ─────►│ e5 "query:" ─► Chroma top-5 ─► промпт с фрагментами ─► Gemini│──► ответ + источники
             │                                 (только по контексту,      │
             │                                  JSON: answer/found/sources)│
             └────────────────────────────────────────────────────────────┘
```

Ключевые решения:

- **Чанкинг** — скользящее окно ~500 символов с перекрытием 100. Граница сдвигается к ближайшему
  абзацу, строке, предложению или пробелу, чтобы не резать слова и цифры. К тексту чанка при
  эмбеддинге добавляется заголовок документа: так фрагмент «Лимиты: до 9 000 рублей» не теряет
  контекст «командировки».
- **Префиксы e5** — модель обучена с `query:` / `passage:`; без них качество поиска заметно падает.
- **Структурированный ответ** — Gemini возвращает JSON (`answer`, `found`, `sources`) по
  pydantic-схеме. Источники фильтруются по реально найденным фрагментам, поэтому выдуманный
  файл в ответ не попадёт.
- **Отказ** — системный промпт запрещает знания извне; при отсутствии ответа модель возвращает
  `found=false` и фразу «В документах нет информации».
- **Бесплатный тариф** — между запросами выдерживается пауза (`GEMINI_MIN_INTERVAL`, по умолчанию 6 с),
  при `429` и `5xx` выполняется повтор: задержка берётся из `retryDelay` в ответе API, иначе
  экспоненциальный backoff (до 6 попыток).

## Структура

```
docs/               8 HR-политик DemoTech (Markdown)
rag.py              ядро: конфиг, чанкинг, эмбеддинги, Chroma, Gemini с ретраями, answer()
ingest.py           индексация docs/ → chroma_db/
app.py              Streamlit-интерфейс
eval.py             оценка качества → eval/results.md
eval/questions.json 20 вопросов с эталоном и источником + 5 вопросов без ответа
```

## Запуск

Нужен Python 3.10+ (проверено на 3.12, Windows 11).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

# ключ: https://aistudio.google.com/apikey
cp .env.example .env        # и впишите GEMINI_API_KEY
# или: export GEMINI_API_KEY=...   (PowerShell: $env:GEMINI_API_KEY="...")

python ingest.py            # индексация (первый запуск скачает модель ~470 МБ)
python eval.py              # оценка качества → eval/results.md
streamlit run app.py        # веб-интерфейс на http://localhost:8501
```

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `GEMINI_API_KEY` | — (обязательна для генерации) | ключ Gemini API |
| `GEMINI_MODEL` | `gemini-flash-latest` | модель генерации |
| `GEMINI_JUDGE_MODEL` | = `GEMINI_MODEL` | модель-судья в eval |
| `GEMINI_MIN_INTERVAL` | `6` | пауза между запросами, с |
| `GEMINI_MAX_RETRIES` | `6` | повторов при 429/5xx |

## Оценка качества

`python eval.py` считает:

| Метрика | Как считается |
|---|---|
| **Retrieval hit@3** | доля вопросов, у которых документ-источник есть среди top-3 фрагментов (также hit@1 и MRR@5) |
| **Точность ответов** | LLM-as-judge: Gemini сравнивает ответ бота с эталоном (совпадение ключевых цифр и фактов) |
| **Верный источник** | бот назвал ожидаемый документ |
| **Ложные отказы** | бот ответил «нет информации», хотя ответ в документах есть |
| **Правильные отказы** | доля 5 «пустых» вопросов (фитнес, 13-я зарплата, собака в офисе…), на которые бот отказался отвечать |

Бесплатный тариф Gemini ограничен по запросам в день, поэтому eval экономит квоту:
- судья оценивает ответы пачками по 10, а не по одному;
- ответы и вердикты кэшируются в `eval/cache/`: если квота кончилась, прогон
  продолжится с того же места при перезапуске.

Флаги: `--retrieval-only` (без Gemini), `--no-cache` (всё заново).

| Метрика | Значение |
|---|---|
| Retrieval hit@1 | 100% (20/20) |
| Retrieval hit@3 | **100% (20/20)** |
| Retrieval MRR@5 | 1.000 |
| Точность ответов (LLM-judge) | _запустите `python eval.py` с ключом_ |
| Правильные отказы | _запустите `python eval.py` с ключом_ |

Подробная таблица по каждому вопросу — в [eval/results.md](eval/results.md).

**Ограничения оценки.** В корпусе 8 документов на разные темы, поэтому найти нужный *документ*
легко: hit@3 = 100% — скорее проверка, что поиск исправен, чем серьёзный бенчмарк. Более строгие
проверки: точность ответов (нужен конкретный факт из конкретного чанка) и отказы. Следующие шаги:
вопросы с перефразированием и вопросы, требующие нескольких документов, оценка на уровне чанков,
сравнение размеров чанков и top-k.
