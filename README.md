# HR RAG-бот DemoTech

Учебный RAG-бот (Retrieval-Augmented Generation), который отвечает на вопросы сотрудников по HR-политикам
вымышленной компании **DemoTech**: отпуска, больничные, удалёнка, онбординг, командировки, обучение,
увольнение, ДМС. Бот отвечает **только** по найденным фрагментам документов, указывает источник,
а если ответа нет — честно говорит «В документах нет информации».

Главная часть проекта — **воспроизводимая оценка качества**: retrieval hit@3, точность ответов
через LLM-as-judge и доля правильных отказов на вопросах «с подвохом».

> Все документы в `docs/` — демонстрационные, компания и цифры вымышлены.

## Стек

| Компонент | Технология |
|---|---|
| Эмбеддинги | `intfloat/multilingual-e5-small` (sentence-transformers, локально, CPU) |
| Векторная БД | ChromaDB, локально в `chroma_db/`, косинусная метрика |
| LLM | Google Gemini через SDK `google-genai` (по умолчанию `gemini-3.1-flash-lite`, на ней получены результаты ниже) |
| UI | Streamlit |
| Оценка | собственный `eval.py`: hit@k, MRR, LLM-as-judge |

## Архитектура

```
             ┌──────────── ingest.py (офлайн) ─────────────┐
docs/*.md ──►│ чанкинг ~500 симв. ─► e5 "passage:" ─► Chroma│──► chroma_db/
             └─────────────────────────────────────────────┘

             ┌──────────────── rag.answer() ──────────────────────────────┐
вопрос ─────►│ e5 "query:" ─► Chroma top-5 ─► промпт с фрагментами ─► Gemini│──► ответ + источники
             │                                 (только по контексту,      │
             │                                  JSON: answer/found/sources)│
             └────────────────────────────────────────────────────────────┘
```

Ключевые решения:

- **Чанкинг** — скользящее окно ~500 символов с перекрытием 100. Граница сдвигается к ближайшему
  абзацу, строке, предложению или пробелу, чтобы не резать слова и цифры. К тексту чанка при
  эмбеддинге добавляется заголовок документа: так фрагмент «Лимиты: до 9 000 рублей» не теряет
  контекст «командировки».
- **Префиксы e5** — модель обучена с `query:` / `passage:`; без них качество поиска заметно падает.
- **Структурированный ответ** — Gemini возвращает JSON (`answer`, `found`, `sources`) по
  pydantic-схеме. Источники фильтруются по реально найденным фрагментам, поэтому выдуманный
  файл в ответ не попадёт.
- **Отказ** — системный промпт запрещает знания извне; при отсутствии ответа модель возвращает
  `found=false` и фразу «В документах нет информации».
- **Бесплатный тариф** — между запросами выдерживается пауза (`GEMINI_MIN_INTERVAL`, по умолчанию 6 с),
  при `429` и `5xx` выполняется повтор: задержка берётся из `retryDelay` в ответе API, иначе
  экспоненциальный backoff (до 6 попыток).

## Структура

```
docs/               8 HR-политик DemoTech (Markdown)
rag.py              ядро: конфиг, чанкинг, эмбеддинги, Chroma, Gemini с ретраями, answer()
ingest.py           индексация docs/ → chroma_db/
app.py              Streamlit-интерфейс
eval.py             оценка качества → eval/results.md
eval/questions.json 30 вопросов с эталоном и источниками + 10 без ответа, по категориям
```

## Запуск

Нужен Python 3.10+ (проверено на 3.12, Windows 11).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

# ключ: https://aistudio.google.com/apikey
cp .env.example .env        # и впишите GEMINI_API_KEY
# или: export GEMINI_API_KEY=...   (PowerShell: $env:GEMINI_API_KEY="...")

python ingest.py            # индексация (первый запуск скачает модель ~470 МБ)
python eval.py              # оценка качества → eval/results.md
streamlit run app.py        # веб-интерфейс на http://localhost:8501
```

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `GEMINI_API_KEY` | — (обязательна для генерации) | ключ Gemini API |
| `GEMINI_MODEL` | `gemini-3.1-flash-lite` | модель генерации |
| `GEMINI_JUDGE_MODEL` | = `GEMINI_MODEL` | модель-судья в eval |
| `GEMINI_MIN_INTERVAL` | `6` | пауза между запросами, с |
| `GEMINI_MAX_RETRIES` | `6` | повторов при 429/5xx/таймауте |
| `GEMINI_TIMEOUT` | `120` | таймаут одного запроса, с |

## Оценка качества

Набор вопросов `eval/questions.json` разбит на категории:

| Категория | N | Что проверяет | Пример |
|---|---|---|---|
| Простые | 20 | прямой вопрос, формулировка близка к тексту | «Какой лимит на стоматологию в ДМС?» |
| Перефразированные | 2 | разговорная лексика, нет общих слов с документом | «Сколько раз можно сходить к мозгоправу по страховке?» |
| Два документа | 4 | ответ собирается из двух политик | «Заболел в командировке — до скольки предупредить и платят ли суточные?» |
| Подвох в цифрах | 4 | неверная посылка, расчёт, лимит поверх процента | «Курсы стоят 14 000 ₽ — сколько вернут?» (50%, но не более 5 000) |
| Нет в документах | 5 | темы, которых нет в корпусе | фитнес, 13-я зарплата, собака в офисе |
| Ловушки | 5 | похоже на реальные темы, но конкретного ответа нет | аренда авто в командировке, очки по ДМС, реферальный бонус |

`python eval.py` считает по каждой категории:

| Метрика | Как считается |
|---|---|
| **Retrieval hit@3** | хотя бы один ожидаемый документ есть среди top-3 фрагментов (также hit@1 и MRR@5) |
| **all@5** | *все* ожидаемые документы попали в top-5, то есть в контекст LLM (важно для вопросов на два документа) |
| **Точность ответов** | LLM-as-judge: Gemini сравнивает ответ с эталоном; неверный итог расчёта, согласие с ложной посылкой или ответ лишь на половину вопроса — ошибка |
| **Источники верны** | бот назвал все ожидаемые документы |
| **Ложные отказы** | бот ответил «нет информации», хотя ответ в документах есть |
| **Правильные отказы** | доля вопросов без ответа и ловушек, на которые бот отказался отвечать |

Бесплатный тариф Gemini ограничен по запросам в день, поэтому eval экономит квоту:
- судья оценивает ответы пачками по 10, а не по одному;
- ответы и вердикты кэшируются в `eval/cache/`: если квота кончилась, прогон
  продолжится с того же места при перезапуске.

Флаги: `--model` / `--judge-model` (переопределить модели), `--retrieval-only` (без Gemini),
`--no-cache` (всё заново). Не запускайте два прогона одновременно: они пишут в одни и те же
файлы кэша и `eval/results.md`.

### Результаты

Прогон от 2026-11-12: генерация и судья — `gemini-3.1-flash-lite`, эмбеддинги `multilingual-e5-small`,
top-k = 5. Набор: 30 вопросов с ответом + 10 без ответа.

| Метрика | Значение |
|---|---|
| Retrieval hit@1 | 93% (28/30) |
| Retrieval hit@3 | **100% (30/30)** |
| Retrieval MRR@5 | 0.961 |
| Точность ответов (LLM-judge) | **90% (27/30)** |
| Верный источник | 90% (27/30) |
| Ложные отказы | 3% (1/30) |
| Правильные отказы | **100% (10/10)** |

По категориям вопросов с ответом:

| Категория | N | hit@3 | all@5 | Точность ответов |
|---|---|---|---|---|
| Простые | 20 | 100% | 100% | 100% (20/20) |
| Перефразированные | 2 | 100% | 100% | 50% (1/2) |
| Два документа | 4 | 100% | 75% | 75% (3/4) |
| Подвох в цифрах | 4 | 100% | 100% | 75% (3/4) |

Отказы: 5/5 на темах, которых нет в документах, и 5/5 на «ловушках», похожих на реальные темы.

Все 3 ошибки — на сложных вопросах:
- **#32** (перефразированный, про отключение учёток в последний день) — ложный отказ, ошибка
  генерации: нужный фрагмент из `07_uvolnenie.md` был в контексте (3-е место), но модель не
  связала «отключат учётки» с «доступ блокируется в 18:00».
- **#36** (отпуск + ДМС при увольнении) — ошибка поиска: `07_uvolnenie.md` не попал в top-5
  (единственный промах all@5), и модель подставила неподходящее правило из положения об отпусках
  («компенсация только за дни сверх 28»), а про расчёт при увольнении не сказала.
- **#40** (подвох в цифрах) — бот назвал правило «50%, но не более 5 000 ₽», но не посчитал итоговую сумму.

Подробная таблица по каждому вопросу и комментарии судьи — в [eval/results.md](eval/results.md).

**Ограничения оценки.** Результаты нельзя считать серьёзным бенчмарком:
- **Корпус маленький — 8 документов** на непересекающиеся темы. Найти нужный *документ* легко,
  поэтому hit@3 = 100% показывает скорее, что поиск исправен, а не что он хорош.
- **Тест простой.** 20 из 30 вопросов — прямые вопросы на один факт, и на них 100%. Сложных
  вопросов (перефразирование, два документа, подвох в цифрах) всего 10, поэтому проценты по
  этим категориям очень шумные: одна ошибка меняет их на 25–50 п.п.
- **Судья — та же модель**, что генерирует ответы (`gemini-3.1-flash-lite`), и она тоже может ошибаться.
  Вердикты стоит проверять вручную (см. разбор ошибок в `eval/results.md`).
- **Один прогон**, без оценки разброса между запусками.

Следующие шаги: больше документов с пересекающимися темами, больше сложных вопросов,
оценка на уровне чанков, сравнение размеров чанков и top-k, независимая модель-судья.
